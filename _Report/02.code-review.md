# TV Channel Controller 코드 리뷰 보고서

## 1. 개요

| 항목 | 내용 |
|---|---|
| 배경 | TDD로 개발되는 TV 채널 컨트롤러 |
| 리뷰 대상 | `src/TVChannelController.cpp`, `test/TVChannelControllerTest.cpp` |

| 작성일 | 2026-05-19 |

본 보고서는 컨트롤러 구현과 Fake 기반 단위 테스트를 중심으로, **단위 테스트 품질·커버리지**, **SOLID 원칙 준수**, **테스트 가능성** 세 관점에서 현재 상태를 평가하고 개선 방향을 제시한다.

---

## 2. 현재 상태 요약

### 2.1 구현 (`TVChannelController.cpp`)

모든 public 메서드와 private `applyChannel()`이 **빈 스텁**이다. 헤더(`TVChannelController.h`)에는 입력 버퍼, 즐겨찾기 목록, 채널 유효성 검사 등 설계 의도가 반영되어 있으나, 구현체는 아직 요구사항을 반영하지 않는다.

### 2.2 테스트 (`TVChannelControllerTest.cpp`)

`FakeTuner`를 생성하고 `TVChannelController`에 주입하지만, **컨트롤러의 어떤 메서드도 호출하지 않는다**. `FakeTuner`의 초기 채널(`"0"`)만 검증하므로, 컨트롤러 동작에 대한 회귀 방지 효과가 없다.

### 2.3 README 대비 진행도

`README.md`의 TO-DO에는 숫자 입력, 선호 채널 토글, 다음 선호 채널 등 **20개 이상의 시나리오 테스트**가 정의되어 있다. 현재 `TVChannelControllerTest.cpp`는 해당 항목 중 **0건**을 충족한다.

## 3. 항목별 리뷰

### 3.1 Unit Test 품질 및 커버리지

| 평가 항목 | 현재 | 판정 | 비고 |
|---|---|---|---|
| 테스트 대상 명확성 | `FakeTuner` 초기값만 검증 | ❌ 부족 | 컨트롤러 SUT(System Under Test)가 관찰되지 않음 |
| 행위 검증 | `pressNumber`, `pressConfirm` 등 미호출 | ❌ 없음 | README 기능 1~3 전부 미검증 |
| 경계값 테스트 | 채널 0, 99, 100+ 시나리오 없음 | ❌ 없음 | README에 명시된 케이스 미구현 |
| 상태 전이 테스트 | 입력 버퍼, 즐겨찾기 토글 없음 | ❌ 없음 | |
| 테스트 이름 | `Stub` | ⚠️ 개선 필요 | 검증 내용을 드러내는 이름 권장 |
| Fake vs Mock 역할 분리 | Fake 테스트 파일 존재 | ✅ 구조 양호 | Mock 테스트는 별도 파일에서 보완 예정 |
| 커버리지(기능) | README 기준 약 0% | ❌ 매우 낮음 | 구현도 스텁이라 의미 있는 커버리지 없음 |

**종합:** 테스트 인프라(GTest, `FakeTuner`)는 갖춰져 있으나, TDD 사이클의 **Red 단계(실패하는 요구사항 테스트)** 가 아직 시작되지 않은 상태에 가깝다.

### 3.2 SOLID 원칙 준수 여부

| 원칙 | 현재 설계 | 판정 | 설명 |
|---|---|---|---|
| **S**RP (단일 책임) | 컨트롤러가 입력·채널 적용·즐겨찾기·튜너 호출을 모두 담당할 구조 | ⚠️ 주의 | 현재 규모에서는 허용 가능. 즐겨찾기 정책이 복잡해지면 분리 검토 |
| **O**CP (개방-폐쇄) | `ITuner` 추상화로 튜너 구현 교체 가능 | ✅ 양호 | `FakeTuner` / `MockTuner` 추가 시 컨트롤러 수정 최소화 |
| **L**SP (리스코프 치환) | `ITuner` 구현체가 인터페이스 계약 준수 | ✅ 양호 | `FakeTuner::setCH` 범위 예외 등 계약이 테스트 더블에 반영됨 |
| **I**SP (인터페이스 분리) | `ITuner` 3메서드만 노출 | ✅ 양호 | 과도한 인터페이스 없음 (`ITuner.h` 수정 불가 제약과도 부합) |
| **D**IP (의존성 역전) | `ITuner&` 생성자 주입 | ✅ 양호 | 구체 튜너에 의존하지 않음 |

**종합:** 헤더 수준의 **의존성 방향과 추상화는 SOLID에 부합**한다. 다만 `TVChannelController.cpp`가 비어 있어 SRP·DIP의 이점이 런타임 동작으로 증명되지는 않는다.

### 3.3 테스트 가능성 (Testability)

| 요소 | 현재 | 판정 | 설명 |
|---|---|---|---|
| 의존성 주입 | `explicit TVChannelController(ITuner& t)` | ✅ 우수 | 테스트 더블 주입 용이 |
| 관찰 가능한 출력 | `tuner.getCurrentCH()`, `getFavoriteChannels()` | ✅ 양호 | Fake로 최종 상태 검증 가능 |
| 내부 상태 노출 | `getFavoriteChannels()` const ref 반환 | ⚠️ 보통 | 테스트 편의는 있으나 내부 표현 누출 |
| private 로직 | `applyChannel`, `isValidChannel` 등 | ✅ 적절 | public API를 통해 간접 검증 가능 |
| Mock 검증 | `TVChannelControllerMockTest.cpp` 스텁 | ❌ 미활용 | `setCH` 호출 횟수·순서 검증 미구현 |
| 결정론적 테스트 | `FakeTuner` 상태 기반 | ✅ 양호 | 외부 I/O·시간 의존 없음 |

**종합:** **테스트 가능한 설계**이나, 테스트 코드가 그 설계를 활용하지 못하고 있다.

## 4. Before / After 코드 예시

### 4.1 단위 테스트 — 컨트롤러 동작 검증

#### Before (현재)

```cpp
TEST(TVChannelControllerTest, Stub) {
    FakeTuner tuner({1, 4, 12, 56});
    TVChannelController ctrl(tuner);
    EXPECT_EQ("0", tuner.getCurrentCH());
}
```

**문제:** `ctrl`을 생성만 하고 버튼 입력을 시뮬레이션하지 않는다. `FakeTuner` 단위 테스트와 중복된다.

#### After (권장)

```cpp
TEST(TVChannelControllerTest, ConfirmAppliesSingleDigitChannel) {
    FakeTuner tuner({1, 4, 12, 56});
    TVChannelController ctrl(tuner);

    ctrl.pressNumber(1);
    ctrl.pressConfirm();

    EXPECT_EQ("1", tuner.getCurrentCH());
}

TEST(TVChannelControllerTest, TwoDigitsApplyOnSecondNumberWithoutConfirm) {
    FakeTuner tuner({1, 4, 12, 56});
    TVChannelController ctrl(tuner);

    ctrl.pressNumber(1);
    ctrl.pressNumber(2);

    EXPECT_EQ("12", tuner.getCurrentCH());
}

TEST(TVChannelControllerTest, PressOtherClearsInputBuffer) {
    FakeTuner tuner({1, 4, 12, 56});
    TVChannelController ctrl(tuner);

    ctrl.pressNumber(4);
    ctrl.pressNumber(5);
    ctrl.pressOther();

    EXPECT_EQ("0", tuner.getCurrentCH());
}
```

### 4.2 구현 — 채널 적용 중심 리팩토링

#### Before (현재)

```cpp
void TVChannelController::applyChannel(int ch) {
}
```

#### After (권장)

```cpp
void TVChannelController::applyChannel(int ch) {
    if (!isValidChannel(ch)) {
        return;
    }
    tuner_.setCH(std::to_string(ch));
}
```

`pressConfirm`, `pressNextFavorite` 등은 모두 `applyChannel()`을 경유하도록 두면, 채널 적용 규칙이 한곳에 모여 SRP와 테스트가 단순해진다.

---

### 4.3 구현 — 숫자 입력 및 확정

#### Before (현재)

```cpp
void TVChannelController::pressNumber(int digit) {
}

void TVChannelController::pressConfirm() {
}
```

#### After (권장 예시)

```cpp
void TVChannelController::pressNumber(int digit) {
    if (digit < 0 || digit > 9) {
        return;
    }

    if (inputBuffer_ < 0) {
        inputBuffer_ = digit;
        applyChannel(digit);
        return;
    }

    int next = inputBuffer_ * 10 + digit;
    if (next > 99) {
        inputBuffer_ = -1;
        return;
    }

    inputBuffer_ = next;
    applyChannel(next);
}

void TVChannelController::pressConfirm() {
    if (inputBuffer_ < 0) {
        return;
    }
    applyChannel(inputBuffer_);
    inputBuffer_ = -1;
}
```

> **참고:** 위 로직은 README의 “두 자리 입력 시 즉시 적용” 등 명세에 맞춘 예시이다. 실제 TDD에서는 README 시나리오 하나당 테스트 하나를 먼저 작성한 뒤, 최소 구현으로 통과시키는 것을 권장한다.

### 4.4 Mock 테스트 — 상호작용 검증 (보완)

`TVChannelControllerMockTest.cpp`도 스텁 상태이므로, Fake 테스트와 함께 아래 패턴을 추가하는 것이 좋다.

#### Before

```cpp
TEST(TVChannelControllerMockTest, Stub) {
    MockTuner mockTuner;
    TVChannelController ctrl(mockTuner);
    EXPECT_TRUE(true);
}
```

#### After (권장)

```cpp
TEST(TVChannelControllerMockTest, ConfirmCallsSetCHOnce) {
    MockTuner mockTuner;
    TVChannelController ctrl(mockTuner);

    EXPECT_CALL(mockTuner, setCH("1")).Times(1);

    ctrl.pressNumber(1);
    ctrl.pressConfirm();
}
```

## 5. 권장 TDD 진행 순서

1. **Red:** README `TVChannelControllerTest.cpp` TO-DO 중 우선순위 높은 항목부터 실패 테스트 작성  
   - 예: `pressNumber(1)` + `pressConfirm()` → `"1"`
2. **Green:** `applyChannel()` → `pressNumber()` → `pressConfirm()` 순으로 최소 구현
3. **Refactor:** 중복 제거, private 헬퍼 정리, 테스트 이름 정비
4. **Mock 보완:** `setCH` / `getCurrentCH` 호출 순서가 중요한 시나리오만 `TVChannelControllerMockTest.cpp`에 추가

## 7. 결론

| 관점 | 요약 |
|---|---|
| Unit Test | 인프라는 갖춰졌으나 **컨트롤러 요구사항을 검증하는 테스트가 없음**. README TO-DO 대비 사실상 0% |
| SOLID | **DIP·OCP·ISP는 헤더 설계에서 잘 지켜짐**. 구현 완성 후 SRP 재평가 권장 |
| Testability | **`ITuner` 주입 구조는 우수**. 테스트가 이를 활용하도록 Red 테스트부터 작성 필요 |

**한 줄 요약:** 설계는 TDD에 적합하지만, **“실패하는 테스트 → 최소 구현” 사이클이 아직 시작되지 않았다.** `TVChannelControllerTest.cpp`를 README 시나리오 기반으로 확장하고, `applyChannel()` 중심으로 `TVChannelController.cpp`를 채우는 것이 다음 단계이다.
